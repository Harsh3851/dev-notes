Flagship project: Hirelane an ATS / hiring pipeline

Jobs, candidates, applications moving through stages (applied → screening → interview → offer → hired/rejected), interviewer feedback. Roles: admin, recruiter, interviewer. Forces auth + RBAC, ~9 related tables, a state machine, file uploads, pagination/search, transactions.

The AI layer is the same product: resume PDF → structured candidate profile (zod-validated) · job↔candidate matching via pgvector · RAG assistant over hiring docs with citations + streaming · tool calls that move a candidate to a stage, with confirmation · evals, prompt-injection defence for uploaded resumes, retries/fallbacks, cost + latency logging.

BoundaryFresh code, fresh data, personal GitHub. Nothing from any employer.

The weekly rhythm

  • Weekdays 8:00–9:30 pm · weekends ~3 h each (build days) · ≈ 14 h/week
  • Sunday = technical test slot (30–45 min) · Friday = weekly review
  • Every second week = mock interview · monthly = full mock
  • A missed day costs one day, never the week — re-plan, never dump the backlog

Daily drill minimum viable session · 15 min

Every session opens with it; on a bad day it is the session:

  • 1 output prediction (JS now; React/Node later)
  • 1 theory question, answered out loud — the 30-second version
  • 1 micro coding problem (5–10 min)
  • 1 recall from the spaced queue — intervals 1 → 3 → 7 → 14 → 30 days; a miss resets to 1. this in callbacks is on the daily list until five clean hits in a row.
