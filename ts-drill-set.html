TypeScript Drill Set

Short drills for each TypeScript lesson. Grows as lessons complete. Predict → check with tsc → compare → only then reveal.

The protocol
  1. Predict what the checker will say (which line, which column, which message) — or what will print.
  2. Check with npx tsc --noEmit --strict file.ts, or ▷ in VS Code.
  3. Compare: did it point where you predicted?
  4. Only then open Hint, and only after a real attempt, Solution.

1Predict● ○ ○

Two tools, two answers. What does npx tsc --noEmit report for this file — and, separately, what does npx tsx print?

let age: number = 24;
age = "twenty-four";
console.log(age);
Hint
One tool compares labels; the other strips them. Only one of them cares that a string went into a number-tagged suitcase.
Solution

Topic · checker vs runner

tsc: age.ts:2:7 - error TS2322: Type 'string' is not assignable to type 'number'.
tsx: twenty-four

tsc reports the mismatch at line 2, column 7 (where "twenty-four" starts). tsx erases the label and runs the plain JS, so the string simply prints. Both behaviours are correct — they're different tools.

2Predict● ○ ○

Which of these lines does the checker reject, and why — one clause each?

interface Book { title: string; pages: number; isbn?: string; }

const a: Book = { title: "Dune", pages: 412 };
const b: Book = { title: "1984", pages: "328" };
const c: Book = { title: "Emma" };
const d: Book = { title: "Ulysses", pages: 730, year: 1922 };
Hint
Three different kinds of mismatch: wrong type · missing required field · extra field not in the shape. One line is fine.
Solution

Topic · interface as a contract

a ✅  isbn is optional, everything else matches
b ❌  pages: "328" is a string — Type 'string' is not assignable to type 'number'
c ❌  Property 'pages' is missing — required fields must be present
d ❌  Object literal may only specify known properties — 'year' is not in Book
3Fix● ● ○

This has three type errors. Find each from the tsc output (read line:col first), then fix so it checks clean and prints Bill: 660.

interface Item { name: string; price: number; qty: number; }

function lineTotal(item: Item): number {
  return item.price * item.qtty;
}

const cart: Item[] = [
  { name: "Pen", price: 10, qty: "6" },
  { name: "Bag", price: 600 },
];

console.log("Bill:", cart.reduce((sum, item) => sum + lineTotal(item), 0));
Hint
A typo in a property name · a string where a number belongs · a missing required field. The checker names all three; your job is to trust its line numbers.
Solution

Topic · reading errors, fixing shapes

item.qtty  → item.qty          // Property 'qtty' does not exist on type 'Item'
qty: "6"   → qty: 6            // string not assignable to number
{ name: "Bag", price: 600 } → add qty: 1   // Property 'qty' is missing
// Bill: 660  (10*6 + 600*1)

Note the first one: in plain JS item.qtty would be undefined, price * undefined would be NaN, and you'd debug a NaN. TS caught the typo before anything ran — this is your #1 bug class, solved.

4Predict● ● ○

Which of these five need an explicit label to be useful, and which are fine inferred? Then: what is the inferred type of each?

const a = 42;
const b = [];
const c = ["x", "y"];
function d(n) { return n * 2; }
let e;
Hint
TS infers from a value that's right there. When there's no value — an empty array, an unassigned let, a parameter — it has nothing to infer from.
Solution

Topic · inference vs explicit labels

a → number     fine inferred
b → any[]      needs a label: const b: string[] = []   (empty array tells TS nothing)
c → string[]   fine inferred
d → n is any   needs a label: function d(n: number)   (parameters ALWAYS need labels;
               with --strict this is an ERROR: "Parameter 'n' implicitly has an 'any' type")
e → any        needs a label: let e: number            (no value → nothing to infer)
5Code● ● ○

Write it: an interface Employee with id (number), name (string), salary (number), optional team (string). Then highestPaid(list: Employee[]): Employee. Test with three employees, then add a deliberate call with an employee missing salary and read the error.

Expectedtsc points at the bad call, naming the missing property; after removing it, the highest-paid name prints.
Hint
Your second-largest scan, or reduce keeping the bigger of two, or sort a copy descending and take [0]. The TS part is only the two labels.
Solution

Topic · interface + typed function

interface Employee { id: number; name: string; salary: number; team?: string; }

function highestPaid(list: Employee[]): Employee {
  return list.reduce((best, e) => e.salary > best.salary ? e : best);
}
// (reduce with no seed is acceptable here because the result type is Employee itself —
//  but it throws on an empty list; a guard is the professional touch.)
