Write totalSalary(employees) — the sum of all salaries.

const employees = [
  { name: "Aman",  salary: 40000 },
  { name: "Priya", salary: 65000 },
  { name: "Ravi",  salary: 52000 }
];
Expected157000
Hint
One value out of many → reduce. Two arguments: the callback, then the seed.
Solution

Topic · reduce, sum pattern

function totalSalary(employees) {
  return employees.reduce((total, emp) => total + emp.salary, 0);
}

Never omit the 0. Without it, reduce starts from element[0] — an object — and you get string garbage.

Three logs. Two traps.

const nums = [9, 80, 7, 100];
const sorted = nums.sort();

console.log(sorted);
console.log(nums);
console.log(sorted === nums);
Hint
What does sort compare elements as, with no comparator? And for arrays, what question does === actually ask?
Solution

Topic · default sort is lexicographic · sort mutates · === is identity

[ 100, 7, 80, 9 ]
[ 100, 7, 80, 9 ]
true

As strings: "100" < "7" < "80" < "9" — first characters decide, so 1 beats 7. sort rearranges the original and returns that same array, so both names point at one object and === is true. Fix: [...nums].sort((a,b) => a - b).

Write groupByAuthor(books) — the titles collected under each author.

const books = [
  { title: "The Hobbit",   author: "Tolkien" },
  { title: "1984",         author: "Orwell" },
  { title: "Silmarillion", author: "Tolkien" },
  { title: "Animal Farm",  author: "Orwell" },

Hint
Count-by's sibling. A first-time key starts as [] instead of 0, and you push instead of adding 1. Push stands alone on its line — never assign its return value.
Solution

Topic · group-by (arrays as object values)

function groupByAuthor(books) {
  return books.reduce((groups, book) => {
    if (!groups[book.author]) {
      groups[book.author] = [];
    }
    groups[book.author].push(book.title);
    return groups;
  }, {});
}

Topic · reduce without an initial value

[object Object]23

With no seed, reduce uses element[0] as the first accumulator and starts at element[1]. Write charCount(str), then mostFrequent(str) which reuses it and returns the most common character.

charCount("javascript");
mostFrequent("javascript");
charCount("");
Expected{ j: 1, a: 2, v: 1, s: 1, c: 1, r: 1, i: 1, p: 1, t: 1 } 'a' {}

Count-by, but the "items" are characters — for...of walks a string directly. For the second function: Object.entries(obj) gives you [key, value] pairs you can sort.
Solution

Topic · strings + count-by + Object.entries

function charCount(str) {
  return [...str].reduce((counts, ch) => {
    counts[ch] = (counts[ch] || 0) + 1;
    return counts;
  }, {});
}

function mostFrequent(str) {
  const counts = charCount(str);          // reuse — don't rewrite
  return Object.entries(counts)
    .sort((a, b) => b[1] - a[1])[0][0];   // highest count, take its key
}
12Code● ● ○

Write secondLargest(nums) — the second largest distinct value. Decide what it returns when there isn't one, and implement that.

secondLargest([12, 45, 45, 3, 22]);
secondLargest([5]);
secondLargest([7, 7, 7]);
Expected22 null null
Hint
One pass, two variables. When a new maximum arrives, the old maximum is demoted. Duplicates of the maximum must not qualify.
Solution

Topic · single-pass scan, O(n) time / O(1) space

function secondLargest(nums) {
  let largest = -Infinity, second = -Infinity;
  for (const n of nums) {
    if (n > largest) { second = largest; largest = n; }
    else if (n > second && n !== largest) { second = n; }
  }
  return second === -Infinity ? null : second;
}

Say the alternative too: [...new Set(nums)].sort((a,b) => b-a)[1] — shorter, but O(n log n) and it copies.

14CodeExplain● ● ●

Write debounce(fn, delay) from scratch. Then write throttle(fn, limit). Test both with the harness, and say in one sentence which one you'd use on a search box and why.

const d = debounce(() => console.log("debounced"), 300);
d(); d(); d();                       // burst of 3

const t = throttle(() => console.log("throttled"), 1000);
t(); t(); t();
setTimeout(t, 1500);
Expected"throttled" immediately · "debounced" once ~300ms later · "throttled" again at ~1500ms (3 lines total)
Hint
Both keep state in a closure. Debounce: cancel the pending timer, schedule a new one — fn runs inside the timer. Throttle: a gate — fn runs immediately, and the timer's only job is reopening.
Solution

Topic · closures in practice

function debounce(fn, delay) {
  let timerId;
  return function (...args) {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn.apply(this, args), delay);
  };
}

function throttle(fn, limit) {
  let open = true;
  return function (...args) {
    if (!open) return;        // dropped, never queued
    fn.apply(this, args);
    open = false;
    setTimeout(() => { open = true; }, limit);
  };
}

Search box → debounce: only the final text matters, so wait until typing stops instead of firing a request per keystroke.

15Code● ● ●

Write flattenDeep(arr) without using .flat(). Then say which line is the base case.

flattenDeep([1, [2, [3, [4, [5]]]], 6]);
flattenDeep([]);
Expected[ 1, 2, 3, 4, 5, 6 ] []
Hint
Loop the items (horizontal). An item that is itself an array is the same problem, smaller — hand it to your own function and spread the result in (vertical). Array.isArray(x) does the test.
Solution

Topic · recursion

function flattenDeep(arr) {
  const basket = [];
  for (const item of arr) {
    if (Array.isArray(item)) {
      basket.push(...flattenDeep(item));
    } else {
      basket.push(item);          // ← BASE CASE: no self-call
    }
  }
  return basket;
}

It terminates because every self-call goes one level deeper into a structure of finite depth. The empty array needs no special code — the loop simply runs zero times.

Write wait(ms) — returns a promise that fulfils with "done" after ms. Then predict this, and run it.

async function main() {
  console.log("start");
  const msg = await wait(500);
  console.log(msg);
  console.log("end of main");
}

console.log("after main()");
Expectedstart after main() done ← ~500ms later (half a second) end of main
Hint
Wrap new Promise((resolve) => …) in a function and return it; pull the resolve lever inside the timer. For the order: await pauses only that function, so the caller's next line runs during the pause.
Solution

Topic · building a promise + async/await ordering

function wait(ms) {
  return new Promise((resolve) => {
    setTimeout(() => resolve("done"), ms);
  });
}

Test your wait honestly: log something only the await could produce (like "received: done"). If you console.log inside the timer instead of calling resolve, the output looks right while the promise stays pending forever.

17Code● ● ●

The boss. Write topSpenders(orders, n) — the top n customers by total paid spend, highest first.

const orders = [
  { customer: "Aman",  amount: 1200, status: "paid" },
  { customer: "Priya", amount: 800,  status: "paid" },
  { customer: "Aman",  amount: 2000, status: "cancelled" },
  { customer: "Ravi",  amount: 500,  status: "paid" },
  { customer: "Priya", amount: 1500, status: "paid" },
  { customer: "Aman",  amount: 300,  status: "paid" }
];

topSpenders(orders, 2);
Expected[ { customer: 'Priya', total: 2300 }, { customer: 'Aman', total: 1500 } ]
Hint
Four steps, each one you've already done: keep only paid → total per customer (object accumulator) → turn that object back into an array of objects (Object.entries + map) → sort descending and take the first n (slice).
Solution

Topic · full pipeline — filter, group-totals, entries, sort, slice

function topSpenders(orders, n) {
  const totals = orders
    .filter(order => order.status === "paid")
    .reduce((sums, order) => {
      sums[order.customer] = (sums[order.customer] || 0) + order.amount;
      return sums;
    }, {});

  return Object.entries(totals)
    .map(([customer, total]) => ({ customer, total }))   // parens: object, not a block
    .sort((a, b) => b.total - a.total)
    .slice(0, n);
}

Two details interviewers probe: returning an object from an arrow needs wrapping parentheses, and slice(0, n) is safe even when there are fewer than n customers.
