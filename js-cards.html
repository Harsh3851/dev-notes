Card 0

Output order: the N/U/T method

Tag every line that prints with one letter, then write the output in three passes. Never "feel" the order.
  1. N = now. A plain line, and anything inside an async function before its first await.
  2. U = urgent. Anything inside .then / .catch / .finally, and everything after an await.
  3. T = timer. Anything inside a setTimeout callback. Shortest delay first; equal delays in the order they were added.
  4. Three passes: all N in code order, then all U in the order they were queued, then all T by delay.
  5. A timer added from inside a U or T callback is still a T, and it queues behind the timers already waiting.
console.log("A");                                // N
setTimeout(() => console.log("B"), 0);           // T
Promise.resolve().then(() => console.log("C"));  // U
console.log("D");                                // N

// N: A D   U: C   T: B
// output: A D C B
Answer before opening
setTimeout(() => log("one"), 100);
Promise.resolve().then(() => log("two"));
(async () => { log("three"); await null; log("four"); })();
setTimeout(() => log("five"), 0);
log("six");
log = console.log. Tag each line, then write the output.

three six two four five one. "three" is N: it is before the first await. "five" (0 ms) beats "one" (100 ms).

Promise.resolve().then(() => console.log("X"));
console.log("Y");
Which prints first?

Y. Every N line finishes before the first U line, even when the promise is already resolved.

setTimeout(() => log("B"), 0);
Promise.resolve().then(() => {
  log("C"); setTimeout(() => log("D"), 0);
});
Output?

C B D. D is a timer added later, so it waits behind B, which was already in line.

Card 1

Promises & async/await

A promise is an empty slot that will get a value later. .then says what to do when it arrives. await waits here for it.
  1. new Promise(fn) runs fn now. resolve(v) fills the slot, reject(e) marks it failed. The first call wins. Never called = pending forever.
  2. .then(fn) = when the slot has its value, run fn with it, then move on. .catch(fn) = the same for a failure. Both always wait for the current normal code to finish.
  3. What a .then callback returns becomes the next .then's input. Braces without return pass undefined.
  4. await slot = wait here until the slot has its value. Only this function waits; the file carries on. A rejection becomes a throw, so use try/catch.
  5. async function always returns a promise. Two awaits in a row run one after the other; await Promise.all([a, b]) runs them together.
function wait(ms) {
  return new Promise(resolve => {
    setTimeout(() => resolve("done"), ms);
  });
}
async function steps() {
  console.log("start");
  await wait(1000);          // pauses steps only
  console.log("after 1 s");
}
steps();
console.log("file end");     // start · file end · after 1 s
Answer before opening
async function load() {
  const a = await wait(500);
  const b = await wait(500);
  return a + b;
}
How long until load() finishes? How do you make it about 500 ms?

About 1000 ms: the second timer starts only after the first finishes. Fix: start both first, then wait for both:
const [a, b] = await Promise.all([wait(500), wait(500)]);

Promise.resolve(2)
  .then(n => { n * 2 })
  .then(x => console.log(x));
What prints?

undefined. The first callback has braces and no return, so it passes nothing on. The next .then receives whatever the previous one returned.

async function five() { return 5; }
console.log(five());
five().then(n => console.log(n));
What do the two lines print?

Promise { 5 }, then 5. An async function always returns a promise; the value is inside it, and .then (or await) takes it out.

Card 2

filter · map · reduce

Three questions. filter: keep this one? map: what does it become? reduce: fold everything into one value.
  1. filter returns true/false per item (same items, fewer). map returns the new item (same count). reduce returns the next acc. None of them change the original; forEach returns undefined.
  2. reduce's callback is (acc, item), acc first. The seed is reduce's second argument. Always pass it.
  3. Object accumulator: acc[key] = (acc[key] || 0) + x. The || 0 turns "no slot yet" into 0. Group-by: if (!g[k]) g[k] = []; g[k].push(item); on its own line.
  4. "Which one is biggest?" is a comparison: reduce (compare the values, return the whole item) or sort a copy then [0]. Never filter.
  5. Top-n recipe: filter → reduce into {key: total} → Object.entries → sort((a, b) => b[1] - a[1]) → slice(0, n) → map(p => p[0]).
const totals = orders
  .filter(o => o.status === "paid")
  .reduce((acc, o) => {
    acc[o.customer] = (acc[o.customer] || 0) + o.amount;
    return acc;
  }, {});

Object.entries(totals)      // [["Aman",2000],["Ravi",5000]]
  .sort((a, b) => b[1] - a[1])  // biggest first
  .slice(0, 2)
  .map(pair => pair[0]);          // ["Ravi", "Aman"]
Answer before opening
What does forEach return?

undefined. It is for side effects only.

const totals = orders.reduce((acc, o) => {
  acc[o.customer] = (acc[o.customer] || 0) + o.amount;
  return acc;
}, {});
Why the || 0?

The first time a customer appears, acc[o.customer] is undefined, and undefined + 2000 is NaN. || 0 supplies the starting value.

[10, 1, 5].sort();
Result?

[1, 10, 5]. The default sort compares as strings. For numbers: [...nums].sort((a, b) => a - b).

Card 3

call · apply · bind

All three let you choose this by hand. Call = commas. Apply = array. Bind = bind now, run later.
  1. fn.call(obj, a, b) runs now, arguments separated by commas.
  2. fn.apply(obj, [a, b]) runs now, arguments in one array.
  3. fn.bind(obj) runs nothing. It returns a new function with this welded on. Call that function later.
  4. bind can pre-fill arguments: intro.bind(me, "Hi")("Delhi"). Call-time arguments are appended after the stored ones.
  5. Bind at the handover: setTimeout(user.greet.bind(user), 1000). A bound function cannot be re-bound; the first bind wins.
function intro(greeting, city) {
  return `${greeting}, I'm ${this.name} from ${city}`;
}
const me = { name: "Harsh" };

intro.call(me, "Hi", "Noida");        // runs now
intro.apply(me, ["Hi", "Noida"]);     // runs now
const hi = intro.bind(me, "Hi");      // nothing runs yet
hi("Delhi");                  // "Hi, I'm Harsh from Delhi"
Answer before opening
Difference between call and apply?

Only how the arguments are passed: commas vs an array. Both run the function immediately.

Does bind run the function?

No. It returns a new function.

const cart = {
  owner: "Asha",
  total(tax, discount) { return `${this.owner}: ${100 + tax - discount}`; }
};
const guest = { owner: "Guest" };
cart.total.bind(guest, 10)(20);
Result?

"Guest: 90". this = guest, tax = 10 stored by bind, discount = 20 added at call time: 100 + 10 - 20.

Card 4

Closures and the loop trap

An inner function keeps the outer function's variables alive after the outer has finished. A backpack it carries with it.
  1. It is a closure when the inner function is handed out (returned, no brackets) and called after the outer function finished, and it still has the variables.
  2. It remembers the variable, not a snapshot. If the variable changes later, the closure sees the new value.
  3. Each call of the outer function packs a new backpack. Assigning (const b = a) only shares the same one.
  4. fn names a function; fn() runs it now. return fn hands it out. return fn() runs it while the outer is still running, which is just scope.
  5. Loop trap: var i is one shared variable, read after the loop ends. let makes a fresh one per round. Read the bounds every time.
function makeCounter() {
  let count = 0;                      // private backpack
  return { inc: () => ++count, get: () => count };
}
const a = makeCounter(), b = makeCounter();
a.inc(); a.inc(); b.inc();
a.get(); b.get();             // 2, 1: separate backpacks

for (var i = 1; i <= 3; i++)
  setTimeout(() => console.log(i));   // 4 4 4
for (let j = 1; j <= 3; j++)
  setTimeout(() => console.log(j));   // 1 2 3
Answer before opening
Two counters from makeCounter(). Do they share count?

No. Each call creates its own count.

const a = makeCounter();   // returns () => ++count
const b = a;
a(); a(); b();
What does b() return?

3. b = a shares the same function and the same backpack. Only another makeCounter() call makes a new one.

for (var i = 0; i < 3; i++) setTimeout(() => console.log(i));
Prints?

3 3 3. One shared i, read after the loop ends. With let: 0 1 2.

Card 5

Debounce & throttle

Both stop a function running too often. A factory runs once and returns a wrapper; the wrapper decides on every event.
  1. Debounce runs once after the burst ends. Every call cancels the pending timer and starts a new one. Search box.
  2. Throttle runs at most once per interval during the burst. Calls in the cooldown are dropped, not queued. Scroll, resize.
  3. The factory runs once and creates the state (timerId or open). The wrapper runs on every event. Per-call decisions live in the wrapper.
  4. Debounce: fn runs inside the timer. Throttle: fn runs immediately; the timer's only job is to reopen the gate.
  5. Forward arguments with (...args) and fn(...args). Attach the returned function to the event, not the original.
function debounce(fn, delay) {
  let timerId;
  return (...args) => {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn(...args), delay);
  };
}
function throttle(fn, limit) {
  let open = true;
  return (...args) => {
    if (!open) return;                       // dropped
    fn(...args); open = false;
    setTimeout(() => { open = true; }, limit);
  };
}
Answer before opening
10 letters typed quickly into a box debounced at 300 ms. How many calls?

One, 300 ms after the last keystroke.

In throttle, what happens to calls during the cooldown?

Dropped. Not queued, arguments lost.

Where does fn run in debounce vs throttle?

Debounce: inside the timer, after the quiet period. Throttle: immediately; the timer only reopens the gate.

Card 6

this

this is a hidden input to every regular function, filled in by whoever calls it. Arrows have none of their own.
  1. Regular function: look at the call. obj.m() gives obj. Called bare gives undefined (strict) or window.
  2. Passed to setTimeout, forEach or a listener: the timer, array or element calls it, not your object. setTimeout gives window (a Timeout object in Node); a listener gives the element.
  3. Arrow: no own this. It borrows from the function it was written inside, permanently. Objects never give arrows a this.
  4. this never flows down into a nested regular function. Each call sets its own.
  5. Fix a lost this: an arrow callback, or .bind(this), or forEach's second argument. this.x is a property on whatever this is, never a local variable.
const user = {
  name: "Harsh",
  hi() { return this.name; },
  later() {
    // regular: the timer calls it bare → undefined
    setTimeout(function () { console.log(this.name); }, 0);
    // arrow: borrows later()'s this → "Harsh"
    setTimeout(() => console.log(this.name), 0);
  }
};
user.hi();                // "Harsh": left of the dot is user
const f = user.hi; f();   // undefined: no owner
f.call(user);             // "Harsh": set by hand
Answer before opening
const f = obj.greet;
f();
What is this inside greet?

Not obj. f is called bare: undefined in strict mode, the global object otherwise.

A regular function passed to setTimeout inside a method. What is this?

Not the object. The timer calls it with no owner: window in a browser, the Timeout object in Node.

Two ways to keep the object's this inside a callback?

An arrow function, or .bind(this) on the regular function.

Card 7

Prototypes & class

Every object has a hidden parent. A lookup asks the object, then the parent, then the grandparent, until found or null.
  1. Methods are written once and live on ClassName.prototype; every instance shares them. Per-object data goes on this in the constructor.
  2. new does four things: makes an empty object, links it to the prototype, runs the constructor with this = that object, returns it.
  3. extends sets the parent. In the child constructor super(...) must come before this. super.method() calls the parent's version.
  4. typeof Dog is "function". d instanceof Animal walks the chain; hasOwnProperty does not.
  5. Classes sit in the TDZ, need new, run in strict mode. Extras: #field private, static on the class, get read like a property.
class Animal {
  constructor(name) { this.name = name; } // own data
  speak() { return this.name + " speaks"; } // prototype
}
class Dog extends Animal {
  constructor(name) { super(name); } // super before this
  speak() { return super.speak() + ", woof"; } // override
}
const d = new Dog("Rex");
d.speak();                    // "Rex speaks, woof"
d.hasOwnProperty("speak");    // false: found on the prototype
Answer before opening
typeof a class?

"function". A class is a constructor function underneath.

Where do class methods live?

On ClassName.prototype, shared by every instance.

In a subclass constructor, what must come before you use this?

super(...).

Card 8

Copies & strings

Spread copies one level only. Strings never change in place: clean, split, work on the array, join.
  1. { ...obj } is shallow: anything nested is still shared. structuredClone(obj) is fully independent.
  2. Every string method returns a new string. The recipe: clean → split → process the array → join.
  3. What you split by decides what map sees: split(" ") gives words, split("") gives letters.
  4. Sort a copy: [...nums].sort((a, b) => b - a). sort, reverse, splice and push mutate; map, filter and reduce never do.
  5. Dedupe: [...new Set(arr)], first-seen order. Second largest: track largest and second, skip duplicates with !==.
const titleCase = s => s.split(" ")
  .map(w => w[0].toUpperCase() + w.slice(1))
  .join(" ");
titleCase("the quick fox");                 // "The Quick Fox"

const countVowels = s => [...s.toLowerCase()]
  .filter(ch => "aeiou".includes(ch)).length;

const dedupe = arr => [...new Set(arr)]; // → [3,1,2]

const copy = { ...user };           // shallow: nested shared
const deep = structuredClone(user);  // independent
Answer before opening
const b = { ...a };
b.inner.x = 1;
Does a.inner.x change?

Yes. inner is shared, because spread copies one level only.

Does name.toUpperCase() change name?

No. It returns a new string. Strings are immutable.

secondLargest([5, 5, 3]);
Returns?

3. Duplicates of the largest are skipped.

Card 9

Arrays & the collect pattern

Basket inside the function, loop the values, push what qualifies, return the basket after the loop.
  1. for...of gives the values. for...in gives the keys as strings. Not for arrays.
  2. The basket is declared inside the function, fresh per call. return comes after the loop, never inside it.
  3. Mutating: push, pop, shift, unshift, splice, sort, reverse. Non-mutating: slice, map, filter, concat, spread.
  4. find → first match or undefined. findIndex → index or -1. some → any? every → all? includes → yes/no.
  5. slice(start, end) copies, end excluded. splice(index, count) removes in place.
function cheapNames(products) {
  const basket = [];                    // fresh per call
  for (const p of products) {           // values, not indexes
    if (p.inStock && p.price < 500) basket.push(p.name);
  }
  return basket;                        // after the loop
}

const a = [3, 1, 2];
a.slice(0, 2);       // [3, 1]  a copy
a.splice(1, 1);      // removes index 1: a is now [3, 2]
a.find(x => x > 2);  // 3
Answer before opening
What goes wrong if you return inside the loop of a collect function?

It exits on the first match, so you return one item instead of all of them.

for (const v of ["a", "b"]) console.log(v);
for (const k in ["a", "b"]) console.log(k);
What does each loop print?

of: a, b (the values). in: "0", "1" (index strings).

Why declare the basket inside the function?

So every call starts empty. Declared outside, results pile up across calls.

Card 10

DOM

Every DOM task is three verbs: grab an element, change it, or listen for an event on it.
  1. querySelector("#id") / querySelectorAll(".cls") take a CSS selector, symbols included. getElementById("id") takes the bare name. Never mix the two.
  2. addEventListener("click", handle) passes the function. handle() runs it now and registers undefined.
  3. e.target is the element actually clicked. e.currentTarget is the element whose listener is running. Events bubble up through the parents.
  4. Delegation: one listener on the parent plus e.target.closest("li") handles every child, including ones added later.
  5. Make → fill → attach: createElement, textContent, appendChild. querySelectorAll returns a static NodeList, not an array.
const list = document.querySelector("#list");

const li = document.createElement("li");    // make
li.textContent = "New task";                // fill
list.appendChild(li);                       // attach

list.addEventListener("click", (e) => {     // delegation
  const item = e.target.closest("li");
  if (!item) return;
  item.classList.toggle("done");
});
Answer before opening
querySelector vs querySelectorAll?

The first match (or null) vs a static NodeList of every match.

btn.addEventListener("click", handle());
Why does this break?

handle() runs immediately, and its return value (undefined) gets registered instead of the function.

event.target vs event.currentTarget?

target is the element actually clicked; currentTarget is the element whose listener is running.

Card 11

Hoisting & TDZ

Before running, JavaScript books a name for every declaration in the scope. What you get early depends on how it was declared.
  1. var exists from the start and holds undefined until its line.
  2. let / const exist from the start but cannot be touched until their line (the TDZ): ReferenceError, and the script stops.
  3. A function declaration is usable above its line, body included.
  4. A function expression (var f = function () {}) follows var rules: calling it early is a TypeError, not a function.
  5. Scope = where a name is visible. Hoisting = when it is usable. Two declarations with the same name: the last one wins.
greet();               // works: hoisted with its body
function greet() { console.log("hi"); }

console.log(x);        // undefined: var exists, value not yet
var x = 5;

console.log(y);        // ReferenceError: TDZ, script stops
let y = 10;
Answer before opening
console.log(a);
var a = 3;
Prints?

undefined. var is hoisted and set to undefined; the assignment happens on its own line.

console.log(b);
let b = 3;
Prints?

ReferenceError. b is hoisted but uninitialised (TDZ) until its line runs, and the script stops there.

greet();
function greet() {}

hi();
const hi = function () {};
Which call works, which throws?

greet() works: a declaration is hoisted with its body. hi() throws a ReferenceError: hi is a const in the TDZ.

Card 12

Coercion

JavaScript quietly converts a value to another type so an operation can work. + is the only operator with a second job.
  1. + with a string on either side joins text. Every other operator (- * / %) converts to numbers.
  2. Left to right: "3" + 4 + 5 is "345". 3 + 4 + "5" is "75" (7 first, then joined).
  3. == converts before comparing. === does not. Always use ===.
  4. Exactly eight falsy values: false 0 -0 0n "" null undefined NaN. Everything else is truthy, including [] and {}.
  5. Form fields and textContent are strings: Number(input.value) || 0 before maths. Say "coerce".
"5" + 1          // "51"
"5" - 1          // 4
"10" + 5 - 5     // 100   ("105" first, then minus)
1 == "1"         // true      1 === "1"   // false
Boolean("0")     // true  (any non-empty string)
Boolean([])      // true  (every object)
Number("abc")    // NaN
Answer before opening
"3" + 4 + 5
Result?

"345". "3" + 4 is "34", then "34" + 5 is "345".

3 + 4 + "5"
Result?

"75". 3 + 4 is 7 first (both numbers), then 7 + "5" is "75".

if ([]) console.log("truthy");
Does it print?

Yes. Every object, including an empty array or empty object, is truthy.

Card 13

Errors

An error is JavaScript saying "I can't continue". Uncaught, everything after that line dies. The name says what kind.
  1. ReferenceError: the name cannot be accessed. Undeclared variable, or the TDZ.
  2. TypeError: the value exists but was used wrongly. null.x, calling undefined, spreading a plain object.
  3. SyntaxError: the file does not parse, so nothing in it runs. RangeError: stack blown, recursion with no base case.
  4. try / catch / finally: finally always runs. An Error keeps its text in .message and its kind in .name.
  5. "Cannot read properties of null" means the bug is in the lookup that produced null. NaN means an operand was undefined. "[object Object]" means an object went where a string was expected.
try {
  JSON.parse("{bad json}");            // throws SyntaxError
} catch (err) {
  console.log(err.name, err.message); // SyntaxError ...
} finally {
  console.log("always runs");
}

function withdraw(balance, amount) {
  if (amount > balance) throw new Error("Insufficient funds");
  return balance - amount;
}
Answer before opening
null.length;
Which error?

TypeError. null exists, but you cannot read properties from it.

After an uncaught error, what still runs?

Nothing after that line in the same script. Callbacks already scheduled (timers, events) can still run later.

When does finally run?

Always. After try, or after catch if something threw, even if try contains a return.
